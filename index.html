About

STATISTICS × ENGINEERING

I'm a statistics student who has done most of my learning by building. Across two internships I've built retrieval over 1.2M+ compliance paragraphs, agentic LLM applications from client requirement specs, and AWS ingestion and monitoring for a lakehouse migration. The lesson I keep relearning: the model is rarely the hard part. Data quality, retrieval, evaluation and failure handling are.

That's where the statistics helps. Inference, experiment design and stochastic processes taught me to ask how a number was produced before trusting it, so I treat an LLM pipeline like any other estimator: define the metric, build a regression set, and track it every time the system changes. That's how the MetricStream RAG pipeline got to a 30% lower hallucination rate.

Outside work I build systems end to end: a real-time prediction-markets exchange with its own matching engine and settlement logic, and a multi-agent orchestrator that won its track at the Cursor Hackathon.

HOW I WORK

Any model can produce an answer. The engineering is knowing, and proving, how often it's right.

  1. Start from the workflow and the person doing it, not the model.
  2. Write the eval before the prompt; keep a regression set.
  3. Make the pipeline observable: inputs, retrievals, outputs, latency.
  4. Keep a human in the loop wherever an error is expensive.
